## 1. 文档目的

本 PRD 描述「内容中转平台」从飞书多维表格 + 本机脚本形态，重构为 **React + FastAPI 全栈 Web 项目** 的需求范围、功能定义与验收标准。

一句话目标：**把原来「飞书填表 → 后台脚本加工 → 飞书回写」的流程，收敛成一个自带登录、自带任务队列、自带素材库的独立 Web 应用。**

---

## 2. 背景与现状

### 2.1 原平台是什么

原平台（`内容中转平台（原版）`）围绕两个核心能力：

| # | 能力 | 现状 |
|---|---|---|
| 1 | **视频加水印**（文字 + Logo，九宫格定位、透明度、画质可控） | ✅ 已实测可用（ffmpeg v7.1） |
| 2 | **图文生成 / 文章编写**（需求 + 参考图 + 搜索关键词 → 文案 + 配图） | ✅ 可用（多厂商 AI + 词库增强） |
| 3 | **生图提示词**（粗略需求 → 可直接喂给生图模型的高质量提示词） | ✅ 可用 |

### 2.2 原平台的问题

原平台强依赖飞书与一堆「脚本 + 计划任务 + 隧道」，存在以下结构性痛点：

1. **强耦合飞书**：数据存在飞书多维表格里，任务的提交、状态、结果都绑死在飞书；换 Base、换应用、权限错配都会导致服务不可用。
2. **无独立账号体系**：内部靠飞书账号，外部靠「网页入口 + 访问口令」，没有真正的用户/角色/权限管理。
3. **任务处理是脚本轮询**：`worker.py` 每 10 秒轮询一次飞书表，靠「写入节点标识再回读」做认领锁；并发、超时回收、失败重试都是手写的临时机制。
4. **素材零散**：媒体文件散落在 `work/input`、`work/output`、飞书附件里，没有统一的素材库。
5. **词库增强依赖外部 Skill**：依赖 Cherry Studio 的 `keyword-lexicon` Skill 与 Node + Playwright，环境脆弱。
6. **配置驱动、缺少可视化**：水印参数、AI 厂商、模型全部写在 `config.json`，改一次要重启服务。
7. **前端缺失**：仅有一个纯静态 Demo（`内容中转平台前端`），其中视频编辑页只有「播放预览 + 素材信息」，**与真实的水印功能无法对应**。

### 2.3 重构目标

- **架构现代化**：前后端分离，React SPA + FastAPI REST API。
- **去飞书化**：自建数据库、自建对象存储、自建任务队列，飞书仅作为**可选的未来对接通道**（本期不做）。
- **功能对齐**：把原平台已跑通的三个核心能力完整搬到 Web 端，补齐缺失的「视频水印」编辑/预览/配置能力。
- **工程可维护**：目录结构、接口契约、数据库、UI 规范全部文档化，可直接进入开发。

## 3. 目标用户与角色

| 角色 | 代号 | 权限概述 |
|---|---|---|
| 超级管理员 | super | 管理员的全部权限 + 初始账号持有、账号接管、审计日志导出（运维级，本期仅保留数据位，不开放 UI） |
| 管理员 | admin | 成员管理、全部素材管理、全部任务管理、**系统设置全部权限**（AI 配置、默认水印、词库、任务队列、存储） |
| 编辑者 | editor | 导入/上传素材、创建内容、提交任务、查看与下载自己的结果 |
| 查看者 | viewer | 只读浏览与下载被授权的素材 |

> 角色沿用前端 Demo 的四级（`super / admin / editor / viewer`）。本期权限粒度到「页面 + 资源归属」，不做字段级 ACL。
>
> **v1.1：系统设置整体下放给管理员。** 超级管理员不再独占任何业务配置项，两者在「系统设置」上的能力完全一致；`super` 仅额外保留账号所有权与审计类能力，用于避免「唯一超管账号丢失导致无人可运维」的风险。

### 4.1 认证与成员（P0）

**功能描述**：用户使用「用户名 + 密码」登录，后端签发 JWT；前端所有 API 携带 Bearer Token。

**用户故事**：
- 作为编辑者，我用管理员分配的用户名密码登录，进入工作台。
- 作为管理员，我在「成员与权限」新增成员、设置角色、重置密码、移除成员。
- 作为查看者，我只能浏览和下载素材，不能提交任务、不能改配置。

**验收标准**：
- [ ] 登录失败（用户名/密码错误）返回 401，前端有明确提示。
- [ ] Token 过期后自动刷新或跳转登录页。
- [ ] 越权访问返回 403（如 viewer 调用「新增成员」）。
- [ ] 移除成员后，该成员立即失去登录能力。

**角色与权限矩阵**：

| 能力 | super | admin | editor | viewer |
|---|:---:|:---:|:---:|:---:|
| 查看工作台/任务/素材 | ✅ | ✅ | ✅ | ✅ |
| 导入本地视频 / 上传素材 | ✅ | ✅ | ✅ | ❌ |
| 提交视频水印/文章/提示词任务 | ✅ | ✅ | ✅ | ❌ |
| 保存草稿到素材库 | ✅ | ✅ | ✅ | ❌ |
| 下载素材与任务成品 | ✅ | ✅ | ✅ | 仅下载 |
| 管理成员 | ✅ | ✅ | ❌ | ❌ |
| **管理系统设置（AI/存储/默认水印/队列）** | ✅ | ✅ | ❌ | ❌ |
| 查看服务状态 | ✅ | ✅ | ❌ | ❌ |
| 账号接管 / 审计导出 | ✅ | ❌ | ❌ | ❌ |

### 4.3 视频水印（P0，本期核心）

**功能描述**：把原 `watermark.py` 的能力做成可视化编辑页。用户**从本地导入视频**（或引用素材库已有视频）→ 配置水印 → 预览效果 → **保存到素材库**（后台渲染）→ 下载成品。

**视频来源（v1.1 新增）**：

| 来源 | 入口 | 说明 |
|---|---|---|
| 本地导入 | 页面右上「导入视频」按钮，或直接拖拽到预览区 | 浏览器读取元信息（格式/分辨率/时长/大小）并本地预览；**此时尚未入库** |
| 素材库已有 | 素材信息卡右上「选择源视频」下拉 | 直接引用 `asset_id`，不重复上传 |

**本地导入约束**：

- 格式白名单：`mp4 / mov / mkv / webm`（优先校验 MIME `video/*`，扩展名兜底）。
- 单文件上限 **2 GB**；超出提示「请先在素材库分块上传，再从素材库引用」。
- 导入后必须成功读取到时长与分辨率才能保存；读取失败给出明确提示并允许重选。
- 本地导入是**会话内引用**（`URL.createObjectURL`），刷新页面即失效；需要长期留存必须走「保存到素材库」。

**页面结构**（详见《UI 设计规范与页面结构》5.2）：
- 左：视频预览区（原视频播放 + 水印效果叠加预览）+ 素材信息卡。
- 右：水印配置面板。

**水印配置项**（与 `config.json` / `WatermarkConfig` 对齐）：

| 分组 | 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|---|
| 文字水印 | 文字内容 | text | `健衡学院` | 可为空 |
| 文字水印 | 位置 | 枚举(九宫格) | 右下 | 左上/上中/右上/左中/居中/右中/左下/下中/右下 |
| 文字水印 | 字号 | number | 40 | px |
| 文字水印 | 颜色 | color | #FFFFFF | white/black/任意色 |
| 文字水印 | 透明度 | number(0~1) | 0.8 | |
| Logo 水印 | 图片 | file/url | 空 | 支持上传 PNG |
| Logo 水印 | 位置 | 枚举(九宫格) | 左上 | |
| Logo 水印 | 宽度 | number | 160 | px，高度等比 |
| Logo 水印 | 透明度 | number(0~1) | 0.85 | |
| 通用 | 边距 | number | 40 | px |
| 通用 | 画质 CRF | number | 20 | 18~28，越小越清晰 |
| 通用 | 编码预设 | 枚举 | medium | ultrafast/fast/medium/slow |
| 通用 | 编码线程数 | number | 8 | 0=自动 |

**约束**：
- 文字与 Logo 至少启用一项，否则不可保存。
- 文字与 Logo 可同时启用（各占一个角）。
- 支持保存「水印方案」作为模板（可设默认），下次直接复用。

**两条产出通道（v1.1 明确区分）**：

| 动作 | 落点 | 是否走任务队列 | 结果 |
|---|---|---|---|
| 保存方案 | `watermark_configs` 表 | 否，同步完成 | 参数模板，不进素材库；可在下拉里选用、可设为默认 |
| 保存到素材库 | `POST /tasks`（type=video）→ worker 渲染 → 写入 `assets` | 是 | 任务中心展示「待处理 → 处理中（带进度）→ 已完成」；完成后成品视频进入素材库，**可下载** |

**用户故事**：
- 作为编辑者，我点「导入视频」选一段本地 mp4，页面立刻显示时长与分辨率；配好「右下 + 40px + 白色 0.8 透明」后点「保存到素材库」，页面跳到任务中心并显示渲染进度条；完成后我在素材库看到「xxx_水印版.mp4」，点下载拿到成品。
- 作为管理员，我在系统设置里把默认水印改成品牌色与固定字号，编辑者打开视频水印页即自动带出。

**验收标准**：
- [ ] 本地导入后能正确读取并展示时长、分辨率、大小、格式；读取失败有明确提示。
- [ ] 预览能生成带水印的**单帧预览图**（非全片处理），文字/Logo 位置、透明度、字号改动实时反映。
- [ ] 点「保存到素材库」后进入任务中心，状态从「待处理 → 处理中 → 已完成」流转，处理中展示进度百分比。
- [ ] 任务完成后，成品视频自动出现在素材库「视频」分类，来源标记为「任务产出」，且可下载。
- [ ] 「保存方案」只在方案列表新增一条，不在素材库产生任何文件。
- [ ] 未导入视频 / 未读取成功时，「保存到素材库」按钮禁用并提示原因。

### 4.4 文章编写（P0，本期核心）

**功能描述**：把原「图文生成」能力做成 Web 编辑页。用户填写结构化需求 + 参考图 + 搜索关键词，AI 生成完整文章（标题/正文/标签/合规自检/搜索覆盖自检），并支持在线二次编辑、导出。

**需求输入字段**（对齐原「需求描述模板」）：

| 字段 | 类型 | 必填 | 可选值/说明 |
|---|---|---|---|
| 平台 | 单选 | 是 | 小红书 / 微博 / 微信公众号 / 抖音 |
| 内容类型 | 单选 | 是 | 科普教育 / 种草带货 / 课程转化 / 活动引流 / 市场分析 |
| 受众档位 | 单选 | 否 | 通俗 / 专业 / 混合（默认） |
| 主题/产品 | text | 是 | |
| 核心卖点 | text | 否 | |
| 字数 | text | 否 | 如「400 字以内」 |
| 补充要求 | textarea | 否 | 也支持整段自由文本 |
| 参考图 | file(多) | 否 | 1~3 张 |
| 搜索关键词 | text | 否 | 触发词库增强 |
| 词库策略 | 单选 | 否 | 自动补采 / 只用现成 / 不启用 |

**输出结构**（AI 返回，严格分节）：

```
【标题】     1 个，≤20 字（小红书），含核心词，可带 1 个 emoji
【正文】     按搜索意图簇组织，1200~2500 字
【标签/话题】 #… #…（8~15 个）
【合规自检】 逐条过医疗合规红线
【搜索覆盖自检】 词条/字数/写入位置/是否覆盖（表格，未覆盖如实说明）
```

**词库增强**（对齐 `lexicon.py` + `coverage-rules.md`）：
- 关键词命中词库 → 取「写作任务包」，按意图簇组织正文，长词正文覆盖、短词进标签。
- 策略「自动补采」：词库缺词时自动采集一次并沉淀；「只用现成」：缺词跳过；「不启用」：只认手填联想词。
- 词库增强失败**不得阻断文章生成**（降级为普通文案）。

**在线编辑**：生成后的文章进入可编辑状态，用户可改标题、正文、标签，改完可保存草稿 / 导出。

**保存草稿（v1.1）**：

- 点击「保存草稿」把**当前编辑器内容**（需求字段 + 标题 + 正文 + 标签 + 自检结果）序列化为一份 Markdown 文档，写入素材库：`type=document`、`ext=MD`、`source=draft`、`folder=草稿 / 文章`。
- 命名规则：`{标题或主题} · 草稿`；同一篇再次保存则**更新同一条草稿素材**（覆盖正文与时间），不产生副本。
- 尚未生成文章时也允许保存，此时保存的是「需求草稿」，正文为空但需求字段完整。
- 保存成功后顶部出现「已保存到素材库 · 刚刚」与「去素材库查看」入口。

**用户故事**：
- 作为编辑者，我选「小红书 / 种草带货 / 通俗」，填主题「气压靴」、核心卖点「轻便」，填关键词「气压靴」选「自动补采」，点「生成」，得到带搜索覆盖自检的完整文章。
- 我手动改了几处正文后「保存草稿」，素材库立刻多了一条文档草稿；稍后回来再改一次再保存，仍然是同一条，不会堆副本。

**验收标准**：
- [ ] 结构化字段可组合成与原平台一致的提示词。
- [ ] 生成结果正确分节（标题/正文/标签/合规自检/搜索覆盖自检）。
- [ ] 带关键词且策略非「不启用」时，输出包含「搜索覆盖自检」。
- [ ] AI 调用失败返回明确错误，不产出空白文章。
- [ ] 「保存草稿」后素材库「文档」分类出现该条目，来源标记「草稿」，可下载为 .md。
- [ ] 同一篇文章重复保存命中同一条素材，不产生重复条目。
- [ ] 支持导出、复制。

### 4.5 生图提示词（P1）

**功能描述**：把粗略需求扩写成可喂给 gpt-image/即梦/通义万相的高质量提示词。

**输入**：需求描述（一段话）+ 可选参考图。

**输出结构**：

```
【English Prompt】 自然语言英文提示词（60~150 词，直接可复制）
【中文对照】       3~5 句中文说明
【关键要素】       主体/构图/光线与色调/风格/画质
【推荐参数】       画面比例/适用模型
```

**验收标准**：
- [ ] 输出严格四节，无多余内容。
- [ ] 支持复制英文提示词全文。
- [ ] 可选下载为 txt。
- [ ] **（v1.1）「保存草稿」把需求 + 四节结果写成文档素材进入素材库**（`source=draft`、`ext=MD`、`folder=草稿 / 提示词`），来源标记为「草稿」，可下载。
- [ ] 同一需求重复保存更新同一条草稿，不产生副本。

### 4.6 任务中心（P0）

**功能描述**：统一的「任务队列 + 结果」视图，替代原飞书「处理状态」列。

**任务模型**：

| 字段 | 说明 |
|---|---|
| 任务名称 | 用户自定义 |
| 任务类型 | 图文生成 / 视频水印 / 生图提示词 |
| 状态 | 待处理 / 处理中 / 已完成 / 失败 / 已取消 |
| 提交人 | 关联用户 |
| 提交时间 / 开始时间 / 完成时间 | 时间戳 |
| 处理节点 | 后台 worker 标识 |
| 失败原因 | 失败时填 |
| 结果 | 按类型：文章（文案）/ 提示词 / 水印视频文件 |

**功能**：
- 列表支持按类型、状态筛选，分页。
- 详情页展示结果（文章/提示词/视频下载）。
- 支持**重试**（失败/已取消 → 待处理）、**取消**（待处理/处理中 → 已取消）。
- 支持**删除**任务。
- 状态实时更新（轮询或 SSE）。
- **（v1.1）产物入库**：视频任务处理完成时，worker 把成品文件写入 `assets`（`source=task`，`source_task_id` 指向该任务），任务详情的「下载成品」直接下载这份素材；删除任务不删除已产出的素材。

**进度展示（v1.1）**：`processing` 状态必须带 `progress`（0~1），前端在状态列渲染细进度条；文本任务进度可为空。

**状态机**：

```
待处理 ──► 处理中 ──► 已完成
   │          │
   │          ├──► 失败 ──(重试)──► 待处理
   │          └──► 已取消
   └──(取消)──► 已取消
```

**验收标准**：
- [ ] 任务提交后立即出现在列表，状态为「待处理」。
- [ ] 后台处理后状态正确流转，结果正确回填。
- [ ] 处理中任务展示进度，进度单调递增至 100%。
- [ ] 视频任务完成后，成品素材自动出现在素材库并标记来源「任务产出」。
- [ ] 失败任务展示「失败原因」，重试后重新进入队列。
- [ ] 长时间「处理中」任务可被超时回收（可配置超时）。

### 4.7 素材库（P0）

**功能描述**：统一管理媒体素材（视频、图片、文档），替代原 `work/` 目录与飞书附件。

**功能**：
- 上传（拖拽/点击，多文件，分块上传大文件）。
- 检索（名称/类型/扩展名）。
- 类型筛选（视频/图片/文档）。
- 批量下载 / 删除。
- 存储用量展示。
- 素材可被视频水印、文章编写页面引用。
- **（v1.1）来源标记与筛选**：每条素材带 `source`（`upload` 手工上传 / `task` 任务产出 / `draft` 草稿），卡片右上显示来源徽标；工具栏可按来源过滤。
  - `task` 类素材点击可回溯到来源任务详情。
  - `draft` 类素材为 Markdown 文档，下载时按 `.md` 落地。

**验收标准**：
- [ ] 上传后生成缩略图（视频取首帧，图片压缩）。
- [ ] 删除素材时给出二次确认。
- [ ] 存储用量来自真实磁盘/对象存储统计。
- [ ] 任务产出的成品、保存的草稿都会自动出现在素材库，并带正确来源徽标。
- [ ] 来源筛选可把「只看草稿 / 只看成品」筛出来。

### 4.8 成员与权限（P0）

**功能描述**：成员账号的增删改查与角色分配，替代原飞书分享权限。

**功能**：
- 成员列表（姓名、用户名、角色、状态、最近活跃）。
- 新增成员（姓名、用户名、初始密码、角色、数据范围）。
- 修改角色、重置密码、移除成员。
- 数据范围：全部素材 / 仅本人创建（对齐 Demo 的 `scopeAll`）。

**验收标准**：
- [ ] 用户名唯一，格式校验（3~20 位字母数字下划线点）。
- [ ] 密码至少 8 位。
- [ ] 角色变更立即生效。
- [ ] 移除成员后无法登录、其提交的任务保留。

### 4.9 系统设置（P1）

**功能描述**：集中管理运行配置，替代 `config.json` 的手工编辑 + 重启。

**权限（v1.1 变更）**：系统设置由 **超级管理员与管理员共同持有**，两者可编辑的配置项完全一致。编辑者、查看者不可见该入口（侧边栏隐藏，直接访问路由返回 403）。

| 分区 | 内容 | 可编辑角色 |
|---|---|---|
| AI 文案模型 | provider / api_key / base_url / model / max_tokens / 系统提示词文件 | super / admin |
| AI 生图模型 | enabled / provider / api_key / model / size（独立于文案模型） | super / admin |
| **默认水印（可自定义）** | 文字开关与内容、文字位置、字号、颜色、透明度；Logo 开关与位置、宽度、透明度；边距、CRF、编码预设、线程 | super / admin |
| 词库 | 数据目录 / 分流阈值(tag_max_len) / 采集超时 | super / admin |
| 任务队列 | 并发数 / 单轮上限 / 认领超时 | super / admin |
| 存储 | 存储位置 / 上限 | super / admin |

**默认水印自定义（v1.1 新增能力）**：

- 设置页的「默认水印」不再只是选择预设，而是提供与视频水印页**同构的参数表单**，可直接编辑上述全部字段并实时预览。
- 保存后写入 `system_settings.watermark_default`；所有用户打开「视频水印」页时以该值为初始配置。
- 支持三种落法：
  1. **保存为全局默认** → 写 `watermark_default`，影响所有人下次打开页面的初值；
  2. **另存为方案** → 在 `watermark_configs` 新增一条命名模板，供下拉选用；
  3. **恢复内置预设** → 回到出厂值（`text=健衡学院 / 右下 / 40px / #FFFFFF / 0.8`）。
- 全局默认只影响「新建」的编辑会话，不追溯修改已提交任务的历史参数。

**约束**：API Key 等敏感项脱敏显示（`sk-****`），保存后立即生效（无需重启，热加载）。

**验收标准**：
- [ ] 管理员账号可进入系统设置并保存任意分区，权限与超级管理员一致。
- [ ] 编辑者侧边栏不显示「系统设置」，直接访问 `#/settings` 被重定向并提示无权限。
- [ ] 保存后配置写入数据库，后台 worker 读取最新值。
- [ ] 敏感字段脱敏展示。
- [ ] 非法配置（如 provider 与 base_url 缺失）给出校验错误。
- [ ] 自定义默认水印保存后，新开视频水印页自动带出该参数（字号/颜色/位置/边距均生效）。
- [ ] 「另存为方案」后，视频水印页方案下拉能看到该模板。

## 5. 非功能需求（NFR）

| 维度 | 要求 |
|---|---|
| 性能 | 视频水印 CPU 编码，1 分钟 720p 约 10~30s；支持并发 2 路视频 / 4 路文本 |
| 上传 | 素材直传单文件 ≤ 50 MB，≥ 50 MB 走分块；视频水印「本地导入」上限 2 GB（会话内引用，不占用服务端带宽，入库时再上传） |
| 可用性 | 任务处理失败自动重试（默认 2 次）；「处理中」超时可回收（默认 30min） |
| 安全 | 密码 bcrypt 加密；JWT 鉴权；API Key 加密存储/脱敏；上传文件类型白名单 + 大小限制 |
| 扩展性 | AI 厂商可插拔（zhipu/dashscope/openai/deepseek/openai_compatible） |
| 可维护 | 前后端分离、分层清晰、接口文档化、数据库迁移脚本化 |
| 兼容性 | 支持 Chrome/Edge 最新两个大版本；桌面优先，响应式降级 |
| 数据安全 | 敏感内容经外部 AI 处理，需在 UI 明确提示「勿提交不该外发的材料」 |

## 6. 范围与里程碑

### 6.1 本期范围（In Scope）

- 上述 4.1~4.8 全部 P0 + 4.5/4.9 的 P1 功能。
- 数据库、对象存储、任务队列、JWT 认证。
- 视频水印、文章编写、生图提示词三条完整链路。
- （v1.1）本地视频导入、成品落素材库、草稿落素材库、自定义默认水印、系统设置对管理员开放。

### 6.2 不在本期范围（Out of Scope）

- 飞书对接（多维表格读写、飞书机器人通知）——保留扩展位，后续可接。
- 真正的视频剪辑（裁剪、拼接、转场、字幕）——水印仅在原片叠加。
- 多租户 / 组织架构。
- 移动端原生 App。
- 生图模型的可视化批量出图工作流（仅出提示词，或单张出图）。

### 6.3 建议里程碑

| 阶段 | 内容 | 产出 |
|---|---|---|
| M1 地基 | 前后端脚手架、DB 模型、JWT、成员/角色 | 可登录 + 成员管理 |
| M2 视频水印 | **本地导入** / 配置 / 预览 / **保存到素材库** / 下载 全链路 | 视频水印闭环 + 成品入库 |
| M3 文章编写 | AI 文案生成 + 词库增强 + 在线编辑 + **保存草稿入素材库** | 文章编写闭环 |
| M4 任务中心 + 素材库 | 统一任务队列 + 进度 + 产物回写 + 素材来源维度 | 平台闭环 |
| M5 系统设置 + 生图提示词 + 打磨 | **自定义默认水印** + 权限下放 + P1 功能 + 联调 | 可交付 |

> M2/M4 存在顺序依赖：视频「保存到素材库」依赖 M4 的产物回写能力，建议 M2 先打通前端导入与任务提交，产物回写在 M4 一并验收。

## 7. 验收总览（一句话）

> 登录系统 → **从本地导入一段视频**配好水印 → 点「保存到素材库」→ 任务中心看到进度跑完 → 回素材库下载带水印的成品；
> 同时能填需求 + 关键词生成一篇带合规自检与搜索覆盖自检的文章，**一键保存草稿直接落到素材库**；
> 管理员可自行修改默认水印与全部系统配置 —— 全程不再依赖飞书。
