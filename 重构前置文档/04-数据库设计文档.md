## 1. 设计约定

- 主键统一使用 `UUID`（`gen_random_uuid()`），API 层以带前缀的字符串暴露（`u_`/`t_`/`a_` 等）。
- 时间字段统一 `TIMESTAMPTZ`（UTC）。
- 布尔字段默认 `false`，非空字段显式 `NOT NULL`。
- 外键一律 `ON DELETE` 按业务选择（见各表），不使用级联删除。
- 枚举在 DB 层用 `VARCHAR` + CHECK 约束，应用层用 Pydantic 枚举校验。
- 所有表含 `created_at`、`updated_at`（`updated_at` 由 ORM 自动维护）。

---

## 2. ER 关系总览

```
users 1 ──── N tasks
users 1 ──── N assets
users 1 ──── N drafts
tasks 1 ──── 1 task_outputs（1:1，按类型冗余到 task_outputs）
tasks N ──── N assets（task_attachments：任务引用的输入/输出素材）
tasks 1 ──── N assets（assets.source_task_id：任务产出的成品，v1.1）
drafts 1 ──── 1 assets（assets.ref_id：草稿对应的 .md 文档，v1.1）
users 1 ──── N watermark_configs
lexicon_keywords（独立，无外键）
system_settings（独立，key-value）
service_status（独立，单行）
```

> `assets` 是**唯一文件实体**：手工上传、任务产出、草稿三种来源共用一张表，靠 `source` 区分，避免「产物」与「素材」两套文件管理。

## 3. 表结构定义

### 3.2 `tasks` 任务表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | UUID | PK | 任务 ID |
| name | VARCHAR(128) | NOT NULL | 任务名称 |
| task_type | VARCHAR(16) | NOT NULL, CHECK | article/video/prompt |
| status | VARCHAR(16) | NOT NULL, CHECK | pending/processing/done/failed/canceled |
| requirement | TEXT | NULL | 需求描述（article/prompt 用） |
| platform | VARCHAR(16) | NULL | xhs/weibo/wechat/douyin |
| content_type | VARCHAR(16) | NULL | science/commerce/course/event/market |
| audience | VARCHAR(16) | NULL | general/professional/mixed |
| keyword | VARCHAR(128) | NULL | 搜索关键词（词库增强） |
| keyword_strategy | VARCHAR(16) | NULL | auto/existing/off |
| error | TEXT | NULL | 失败原因 |
| node | VARCHAR(64) | NULL | 处理节点标识（worker-1#pid） |
| **progress** | SMALLINT | NOT NULL DEFAULT 0, CHECK 0~100 | **v1.1** 处理进度百分比，仅 `processing` 有意义 |
| **save_to_assets** | BOOLEAN | NOT NULL DEFAULT true | **v1.1** 产物是否写入素材库（video 任务生效） |
| **output_asset_id** | UUID | FK→assets.id, NULL | **v1.1** 冗余一份成品 ID，省一次 join 查 detail |
| retry_count | INTEGER | NOT NULL DEFAULT 0 | 已重试次数 |
| created_by | UUID | FK→users.id, NOT NULL | 提交人 |
| started_at | TIMESTAMPTZ | NULL | 开始处理时间 |
| finished_at | TIMESTAMPTZ | NULL | 完成时间 |
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT now() | |
| updated_at | TIMESTAMPTZ | NOT NULL DEFAULT now() | |

**索引**：`INDEX(status, task_type)`、`INDEX(created_by)`、`INDEX(created_at DESC)`、`INDEX(status, started_at)`（超时回收扫描用）。

**状态流转**：`pending → processing → done|failed|canceled`；`failed/canceled → (retry) → pending`。

### 3.4 `assets` 素材表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | UUID | PK | 素材 ID |
| name | VARCHAR(255) | NOT NULL | 素材名（上传时取原文件名去扩展名，可改） |
| type | VARCHAR(16) | NOT NULL, CHECK | video/image/document/other |
| ext | VARCHAR(16) | NULL | 扩展名（大写，如 MP4 / MD） |
| mime | VARCHAR(128) | NULL | MIME 类型 |
| size_bytes | BIGINT | NOT NULL | 文件大小 |
| **source** | VARCHAR(16) | NOT NULL DEFAULT 'upload', CHECK | **v1.1** `upload`（手工上传/导入） / `task`（任务产出） / `draft`（草稿） |
| **source_task_id** | UUID | FK→tasks.id, NULL | **v1.1** 来源任务（`source=task` 时必填） |
| **ref_id** | UUID | NULL | **v1.1** 关联业务对象 ID（`source=draft` 时指向 `drafts.id`） |
| storage_key | VARCHAR(512) | NOT NULL | 存储对象键（本地路径或 S3 key） |
| thumbnail_key | VARCHAR(512) | NULL | 缩略图存储键 |
| folder | VARCHAR(128) | NULL | 目录/分类，如 `产物 / 视频`、`草稿 / 文章` |
| **duration_seconds** | INTEGER | NULL | **v1.1** 视频时长（ffprobe 复算） |
| **width** | INTEGER | NULL | **v1.1** 视频/图片宽 |
| **height** | INTEGER | NULL | **v1.1** 视频/图片高 |
| created_by | UUID | FK→users.id, NOT NULL | 上传人 / 产物归属人 |
| deleted_at | TIMESTAMPTZ | NULL | 软删除时间 |
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT now() | |
| updated_at | TIMESTAMPTZ | NOT NULL DEFAULT now() | |

**索引**：

- `INDEX(type)`、`INDEX(source)`、`INDEX(created_by)`、`INDEX(folder)`、`INDEX(deleted_at)`
- `UNIQUE(source_task_id) WHERE source='task'` —— 一个任务只产出一个成品，重试覆盖不新增
- `UNIQUE(ref_id) WHERE source='draft'` —— 一份草稿只对应一个 .md 素材

> 软删除：`deleted_at` 非空即视为已删除，物理文件由后台延迟清理。
>
> `source=task` 的素材在任务被删除后**仍然保留**（`source_task_id` 置空或标记孤儿），因为用户可能已经把它引用了。

### 3.5 `task_attachments` 任务-素材关联表（N:N）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | UUID | PK | |
| task_id | UUID | FK→tasks.id, NOT NULL | |
| asset_id | UUID | FK→assets.id, NOT NULL | |
| role | VARCHAR(16) | NOT NULL | input_video / ref_image / output_video / output_prompt / output_image |

**索引**：`UNIQUE(task_id, asset_id, role)`、`INDEX(asset_id)`。

### 3.6 `watermark_configs` 水印方案表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | UUID | PK | 方案 ID |
| name | VARCHAR(64) | NOT NULL | 方案名 |
| is_default | BOOLEAN | NOT NULL DEFAULT false | 是否默认 |
| config | JSONB | NOT NULL | 水印配置（见下） |
| created_by | UUID | FK→users.id, NOT NULL | 创建人 |
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT now() | |
| updated_at | TIMESTAMPTZ | NOT NULL DEFAULT now() | |

**`config` JSONB 结构**（v1.1 明确布尔开关，与 `system_settings.watermark_default` 同构）：
```json
{
  "text_on": true,
  "text": "健衡学院",
  "text_position": "right_bottom",
  "font_size": 40,
  "font_color": "#FFFFFF",
  "text_opacity": 0.8,
  "logo_on": false,
  "logo_asset_id": null,
  "logo_position": "left_top",
  "logo_width": 160,
  "logo_opacity": 0.85,
  "margin": 40,
  "crf": 20,
  "preset": "medium",
  "threads": 8
}
```

**索引**：`INDEX(created_by)`；`is_default` 通过部分唯一索引保证每个用户至多一个默认：
`CREATE UNIQUE INDEX uq_default_per_user ON watermark_configs(created_by) WHERE is_default;`

> 与全局默认的区别：`watermark_configs` 是**命名模板**（用户可选可存），`system_settings.watermark_default` 是**全站初值**。两者字段结构完全一致，便于互相转换（设置页「另存为方案」即把 default 复制成一条 config）。

### 3.7 `drafts` 草稿表（文章 + 提示词）

> **v1.1**：由 v1.0 的 `article_drafts` 升级而来。文章草稿与提示词草稿字段差异大但生命周期一致，合并为一张表用 `kind` 区分，减少一套表与一套接口。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | UUID | PK | 草稿 ID |
| **kind** | VARCHAR(16) | NOT NULL, CHECK | `article`（文章草稿）/ `prompt`（提示词草稿） |
| title | VARCHAR(255) | NULL | 文章标题；提示词草稿可为空 |
| platform | VARCHAR(16) | NULL | 仅 article：xhs/wechat/... |
| content_type | VARCHAR(16) | NULL | 仅 article |
| audience | VARCHAR(16) | NULL | 仅 article |
| requirement | TEXT | NULL | 生成需求（两者都用） |
| body | TEXT | NULL | 仅 article：正文 |
| tags | JSONB | NULL | 仅 article：标签数组 |
| compliance_check | TEXT | NULL | 仅 article |
| coverage_check | TEXT | NULL | 仅 article：搜索覆盖自检表 |
| **prompt_json** | JSONB | NULL | **仅 prompt**：`{prompt_text, prompt_cn, elements, params}` |
| **asset_id** | UUID | FK→assets.id, UNIQUE, NULL | **v1.1** 草稿对应的 .md 素材（保存时同事务写入） |
| source_task_id | UUID | FK→tasks.id, NULL | 来源任务（可空） |
| created_by | UUID | FK→users.id, NOT NULL | |
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT now() | |
| updated_at | TIMESTAMPTZ | NOT NULL DEFAULT now() | |

**索引**：`INDEX(created_by, kind)`、`INDEX(updated_at DESC)`、`UNIQUE(asset_id)`。

**约束**：

- `kind='article'` 时 `body` 可空（需求草稿），`prompt_json` 必须为 NULL。
- `kind='prompt'` 时 `prompt_json` 非空，`body/tags/coverage_check` 必须为 NULL。
- 同一 `id` 反复保存只 `UPDATE`，并同步覆盖 `asset_id` 指向的那条素材的 `size_bytes / updated_at`，**不新增素材**。

## 4. 索引与约束汇总

| 表 | 索引/约束 | 用途 |

## 5. 数据生命周期

| 场景 | 策略 |
|---|---|
| 用户移除 | 软删除 `is_active=false`，保留其任务/素材 |
| 素材删除 | 软删除 `deleted_at`，物理文件延迟 7 天清理 |
| 任务删除 | 硬删除任务行 + task_outputs + task_attachments，但**不删素材**；`assets.source_task_id` 置 NULL，成品降级为普通素材 |
| **任务产物** | `source=task` 的素材独立于任务存续，用户可单独删除 |
| **草稿保存** | 同事务内 upsert `drafts` + 覆盖对应 `.md` 素材；重复保存不新增记录 |
| **草稿删除** | 删除 `drafts` 行并软删其 `asset`（文件延迟清理） |
| 词库 | 长期保留，`updated_at` 超过 N 天可提示刷新 |
| 服务心跳 | 单行 upsert，无历史 |

## 6. 迁移与种子数据

### 6.1 Alembic 迁移

- 每次 schema 变更生成一个迁移脚本，随版本库提交。
- 首次部署执行 `alembic upgrade head` 建全表。

### 6.2 种子数据（seed）

首次部署自动写入：

1. **初始超级管理员**：`username=admin`，密码由环境变量 `ADMIN_INITIAL_PASSWORD` 注入，首次登录强制改密。
2. **系统设置默认值**：AI 厂商默认 `deepseek`、worker 并发、存储本地路径等。
3. **默认水印**：写入 `system_settings.watermark_default`，`text=健衡学院`、右下、40px、白色 0.8 透明（可在系统设置页自定义，`POST /system/watermark-default/reset` 可恢复本值）。

## 7. 容量与扩展预估

| 表 | 增长速度 | 备注 |
|---|---|---|
| assets | 与素材上传量线性 | 大文件存对象存储，表只存元数据 |
| tasks | 与任务量线性 | 建议按月归档历史任务 |
| task_outputs | 与 tasks 1:1 | 文章 JSON 体积可控 |
| lexicon_keywords | 慢增长 | 每个关键词一行 |
| system_settings | 恒定 | 几十行 |

> 磁盘消耗主要在**对象存储**（视频文件），不在数据库。存储配额由 `storage.quota_bytes` 管控。
